# SOP 07｜AI 模板 / 微工具：从第十次重复需求开始


## 真人故事与证据边界

[EN10 Angela：自动化产品化（多人工程团队）](../cases/real-en10.md)；[CN06 失败案例：半年零收入](../cases/real-cn06.md)；[CN08 老周：音乐版权收入自述](../cases/real-cn08.md)。

**请先读原始来源和「不能推断」部分。** 受访者披露的报价、收入或效率不等于独立审计，也不等于本教程可保证复制。完整矩阵见 [18 个真实案例索引](../cases/REAL-CASE-INDEX.md)。

## 何时适合做？

当你在**真实交付中多次遇到同类问题**，至少三位真实目标用户愿意体验，且你能维护它时。没有上述证据就先留在服务阶段。工具销量、收入增长均不可事先保证。

## 最小样例（虚构）

多个客户在报价前都要算“订单到账减工具费、渠道费和工时后的实际时薪”。先做一个离线计算表，填四项输出一项，不做注册、支付、聊天机器人、云账号。自用通过后让3位目标用户试用。

## 七步SOP

1. 收集至少三条真实、可匿名化的重复需求；若不足，继续交付服务。
2. 写用户输入/输出和验收样例；先让人看懂产品做什么。
3. 画最小界面：输入→算例→结果→导出。默认本地使用。
4. 用 AI 协助写代码或表格，人工检查金额精度、边界、空值、数据存储。
5. 让3位目标人群在你不讲解的情况下完成操作，记录所有卡点。
6. 提供明确的定价/授权/售后说明；任何付费流程都要有可核对退款条件。
7. 用真实付费、重复使用和客服成本决定保留或停止。

## 交付物

一个可下载工具或可复制模板、README、三条示例输入输出、常见错误、更新记录、授权文件、数据如何处理说明。不要把免费第三方软件重新包装假称原创。

## 风险

产品需要维护，AI API 可能变价，用户也可能只需要一次。设计停止服务与备份办法。没有支付意愿就不要继续堆功能。

## 从现有交付中抽取一个可售模板，而非先造 SaaS

**先找重复证据**：至少记录三次彼此独立的类似问题；采访客户上次怎样完成、实际耗时、为什么没用现有免费产品。只有“有人夸我做得好”不够。若没有复购或付费行为，仍属于未验证需求。

**最小示例**：虚构的“岗位 JD 到面试提纲”模板，用户只输入公开 JD 与自己手工确认的经验摘要，不触碰他人身份证、敏感个人信息。交付一个本地 Markdown 模板+三条虚构样例+错误检查清单+使用说明，不需要注册、购买服务器或收集邮箱。

**制作七步**：列输入字段 → 写合法使用范围 → 设计空白模板 → 做 3 个虚构例子（新手/转岗/经验不足）→ 检查三种失败输入 → 找三人试用并观察卡住位置 → 做清楚版本号、退换/更新说明及支持范围。

**验收**：首次使用者在无人指导下，能根据 5 分钟说明得到可编辑成果，遇到未知事实不被引导造假；无法打开/无法按步骤执行则不出售。若模板依赖第三方服务，必须提示订阅、区域可用性、稳定性与可能额外成本，不能宣传永久免费。

**变现模型的分别**：单次模板授权、定制服务、维护订阅、企业授权的权利和售后责任不同，单独注明交付范围与个人信息收集边界。AI 生成的素材、第三方模板、软件库并非一概可转售。优先查版权和商业许可。

**什么时候才做 SaaS**：有人主动反复购买或要求团队协作；你有稳定的部署/安全/维护能力，并能履行用户数据处理责任。没有这些条件，先把模板卖明白，再判断建系统的机会成本。

## 售前自助验收：一个陌生用户能否按说明完成任务？

把模板发送给一位未参与研发的试用者，只提供公开的使用说明，不在旁边口头指导。记录他用多少时间找到入口、哪些字段看不懂、导出文件是否完整、是否无意输入了敏感信息、失败时有没有明确提示。若试用者离开你就无法使用，说明你卖出去的仍然是咨询服务，应该如实说明，不应该将其夸大为“全自动产品”。完成一次修复后让第二位试用者再做相同测试，把第一次的实际反馈与修改记录保存。正式出售之前，要把产品包含的内容、第三方依赖、预计更新策略、售后支持时间、取消和退款规则书面公开；千万不要暗示会持续维护永久版本。
