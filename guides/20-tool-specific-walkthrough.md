# 20｜七类交付：从 AI 对话到客户可打开的最终文件

AI 在这套流程里充当草稿和重复劳动助手；项目责任仍由交付者承担。这里使用**模型无关**的 Prompt，不把某个平台某个按钮写成永远有效的操作步骤。

## 通用四屏法

1. **资料页**：只有已授权输入，逐条标记公开/虚构/客户允许使用。
2. **AI 草稿页**：粘贴 [限定输出范围的提示词](../prompts/14-output-verification.md)，要求写明未知信息和原文证据。
3. **核查页**：人工核对数字、姓名、法律声明、链接、图片权属、可编辑性；错一项改一项。
4. **交付页**：输出客户事先同意的格式；有版本号、验收点、后续变更方法、素材授权清单。

## 不懂技术也能做的具体操作

**求职**：公开 JD → 按要求拆表 → 用虚构简历生成差距表 → 本人核对 → 输出 Markdown/PDF 诊断。**商家**：经确认菜单/课程事实 → FAQ → 七天选题 → 不编营业时间和价格 → 输出文档。**调研**：五个公开网页 → 保存标题与链接 → 表格比对 → 未找到写“未查到” → 输出带出处矩阵。

**短视频**：脚本需求 → 证据来源 → 一段可剪的镜头清单 → 只用自制或有商用权的素材 → 人审字幕和 AI 标识。**自动化**：模拟 CSV → 明确规则 → 生成审核表 → 20 条测试用例 → 客户确认 → 保留人工应急方案。**PPT**：来源→大纲→每页结论与证据→可编辑页→全屏检查。**数字产品**：重复人工服务记录→最小模板→三人试用→支付意愿→附版本/退款规则。

## 统一交付包结构

```text
ORDER-001/
  00-readme.md           本次范围、输入约定与联系方式（内部版）
  01-source-register.csv 来源、授权、核验日期（必要时仅向客户提供）
  02-deliverable.md       已核验的交付物；实际格式由合同决定
  03-qa.csv               自检与未解决问题
  04-acceptance.md        客户的最终验收记录
```

注意：示例目录仅作本地管理，**不得连同真实客户数据一起提交公共 GitHub**。参考 [完整演示案例](../cases/04-complete-funnel-demo.md)。
