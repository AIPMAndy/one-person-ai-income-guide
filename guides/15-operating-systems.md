# 15｜一人工作室最小运营系统：把客户交付做稳定

先从文件夹和表格开始。只要你能一个人服务一位客户，就不必采购 CRM、服务器或自动化平台。**实际业务一周 3 单以上且有重复操作，再考虑自动化。**

## 文件目录与命名规则

`clients/项目代号/00-授权/01-输入/02-工作稿/03-核验/04-交付/05-对账/06-删除记录/`。公开 GitHub 上**禁止上传此文件夹**，即使客户名字已打码，也可能含商业秘密。内部文件不必写客户真实姓名；采用不泄露身份的代号与有限权限。

建议 `YYYYMMDD_客户代号_交付物_v01.md`，正式稿 `vFINAL` 仅由约定验收版本产生。客户反馈必须通过变更记录转移到下一版，避免口头需求无限扩大。

## 每周固定节奏（一个人可执行）

| 周期 | 工作 | 留下的凭证 |
|---|---|---|
| 每天 15 分钟 | 查即将到期、已收未交付、风险工单 | 今日优先级清单 |
| 周一 | 复核本周交付容量，不超过你能人工核验的数量 | 容量表与交期 |
| 周二/三 | 有许可地沟通新客户、展示一份真实样稿 | 线索更新 |
| 周四 | 老客户交付/复购访谈，记录反馈 | 质量复盘 |
| 周五 | 对账、备份、清理已过期资料、更新模板 | 对账与删除记录 |

## 交付品质门槛

任何 AI 生成服务先过四级：**输入合法 → 输出事实核对 → 格式与可用性检查 → 客户验收记录**。自动化必须增加权限、测试、日志脱敏与回滚。能提供“一键生成”不等于满足客户的业务 SLA。

## 什么值得自动化

只有同时满足**高频、规则稳定、错误可逆、可计算收益**的部分才纳入 Agent。优先从 CSV 整理、文件格式转换、非敏感草稿分类做起；涉及支付、帐号权限、发布、删除和陌生人外发消息，都设置明确的人审闸门。

若流程故障，先暂停触发，回退到手工，保留非敏感错误摘要，修复后用独立测试集复验。详见 [AI 工作流 SOP](../playbooks/05-workflow-automation.md)。
