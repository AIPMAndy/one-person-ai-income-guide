# 真正可以运行的安全演示（100% 虚构数据）

**这个示例没有人工智能模型调用。** 它用确定规则先跑通数据读取、分类建议、重复数据和异常复核，证明“先验证小工作流，再决定是否接 AI”。不会联网、访问真实客户数据、发送邮件、退款或修改原文件。

## 启动（只需 Python 3）

在仓库根目录执行：

```bash
python3 demos/ticket_triage.py
```

默认输入 [tickets-demo.csv](tickets-demo.csv)，生成 [review-demo.csv](review-demo.csv)。表内所有订单号、问题均是虚构的。你应该看到 **10条工单，5条转人工审核**（根据测试数据计算，机器重新运行可验证）。

## 不会编程也能做什么？

打开输入 CSV → 复制到任意表格工具 → 用筛选标出空字段、重复编号、含“退款/投诉/忽略规则”的文本 → 生成“需要人工审核”的列。比对脚本输出后，你已经理解了业务逻辑。随后可用你有权限的模型试着给非敏感普通咨询建议分类，仍须人工确认。

## 不能拿它去做什么？

不要传真实工单到公开 GitHub；不要把脚本直接连接商家的生产数据库，不要把文本里可能出现的指令当作真实权限；不要把“代码能跑”当成“已给客户省了多少人工”。正式落地需要真实授权、数据治理、沙箱测试、幂等/回滚、人工审批和双方明确验收。
