# 提交真实案例的方式：证据优先，隐私优先

欢迎普通人、客户及服务提供者提交可复核的真实经历（成功与失败均可）。**不要把身份证、手机号、支付二维码、银行卡、Token、合同全文、内部聊天记录贴进公开 GitHub Issue。**

1. 用 [案例证据模板](../templates/real-case-verification.md) 在本地写清「起点 → 客户需求 → AI 参与 → 成交证据 → 交付验收 → 实收 → 返工 → 失败与限制」。
2. 记录可公开的原始网址/署名及授权范围；客户身份隐去但保留可核验的行业类型与结果口径。
3. 收入仅披露得到授权的金额或区间；区分报单、实收、退款、税费、成本与利润。不要上传原始流水或支付记录；需要验证时通过安全渠道与维护者协商，仅发布经核准的脱敏摘要。
4. 对每一个商业结果，确认来源是否由当事人签字/回复认可，若只有当事人口述则标「自述未审计」。
5. 若结果为0单或退款，仍欢迎提交；失败的停损理由同样重要。
6. 即便已授权，项目维护者仍可因隐私、权属与事实不足拒绝发表。不同国家合规义务需另核对。

**合格示例（纯虚构字段结构）：**「2026-01，内容服务，客户已授权匿名；联系7人、访谈3人、报价2单、实收1单人民币X元，直接成本Y，投入Z小时；客户验收通过；证据核验人已查看脱敏记录并确认。」这只是填写格式，**不是实际交易**。
